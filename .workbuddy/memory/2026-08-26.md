## 待办详情弹窗两个问题的修复（10:50-11:25）

### 问题 1：`ReferenceError: _a_visible is not defined`
- **现象**：微信开发者工具报 `_a_visible is not defined`，发生在 TodoDetailPopover 组件（首页/我的待办点卡片触发）。
- **根因（深挖 30+ 分钟确认）**：生产构建中，TodoDetailPopover 模块若把解构出的绑定命名为 `visible`，构建管线会把 `!visible` 错误改写成**未声明**的 `_a_visible`（且 `!` 丢失）→ 运行时 ReferenceError。与 webpack 缓存无关（清缓存全量重编仍复现）；单独跑 babel/babel-loader 输出均干净，说明问题出在 weapp 构建管线的模块级处理，具体机制未完全定位，但**改名即可规避**。
- **修复**：`TodoDetailPopover/index.tsx` 内部绑定 `visible` → `isOpen`（解构 `{ visible: isOpen }`），对外 prop 名 `visible` 不变。产物验证 `_a_visible` 0 处。
- **注意**：组件头部 JSDoc 已写明该坑，勿改回 `visible` 绑定名。

### 问题 2：关闭待办详情弹窗 → 底层 ScrollView 回顶
- **现象**：点卡片开详情弹窗正常，关弹窗时底层容器滚动条被触发、内容整页滚到顶部。
- **根因**：`useOverlayScrollFreeze` 的 `unfreeze` 释放 pin 时把 `scrollTop` prop **移除** → Taro runtime `removeAttribute` 置 `''` → base.wxml 恒渲染 `scroll-top="{{p32}}"`，微信把 `scroll-top=""` 当 0 → 回顶。
- **修复**（`src/hooks/useOverlayScrollFreeze.ts`）：pin 改为**粘性保持**——首次 pin 后 `lastPinRef` 常驻，`freezeProps` 永不移除 `scrollTop`（scroll-top 是一次性命令，保留旧值不会卡住后续滚动）。开层/关层/FAB 收起均不再触发回顶。
