## 关键教训：布局判定须与渲染策略严格一致
**bug**：判定 "是否放得下" 用固定 `gap=[12rpx]` 估算，但渲染用 `gap-[12rpx] justify-between`——估算偏严、渲染偏松。结果：2 个标签场景被错判为 "放不下完整文字"，实际显示成了纯图标。

**修复要点**：
- 估算时 `TAG_GAP_RPX = 0`（不计入间隔，因为 justify-between 会自然撑开）
- 字符宽度估到 30rpx 更接近中文真实（含字间距/字体）
- 渲染维持 `gap-[12rpx] justify-between`——保证 "不挨在一起 + 留有呼吸感"
- 文字友好余量提到 24rpx

**普遍原则**：UI 自适应降级时，"判定逻辑"必须匹配 "真实渲染模式"——若用 flex/spacing 撑开间隔，估算就不该把这部分间隔当固定值算入。这条经验适用于所有自适应降级场景。

## 真·bug：useMemo 返回字段名与外层解构不一致 → 按钮文字永远 undefined

**症状**：连续多轮调整 `TAG_GAP_RPX`/`TAG_TEXT_RPX`/`TEXT_FRIENDLY_MARGIN_RPX` 都没法让按钮显示文字——再宽的预算也无济于事，因为渲染拿到的 `navLabel`/`callLabel` 永远是 `undefined`。

**根因**（`src/components/home/campus-card/index.tsx`）：
```ts
const { mode, navLabel, callLabel } = useMemo(() => {
  const candidates = [{ mode: 'row', nav: '导航到店', call: fullCall }, ...];
  for (const c of candidates) {
    if (...) return c;          // ← 返回 { mode, nav, call }
  }
  return { mode: 'split', nav: '导航到店', call: fullCall };
}, [...]);
```
外层解构是 `navLabel` / `callLabel`，跟 `c.nav`/`c.call` 字段名对不上 → 解构出来永远是 undefined → 渲染到 `TagActionButton` 的 `label` 也是 undefined → `{label ? <Text>{label}</Text> : null}` 走空值分支 → 永远只剩图标。

**为什么前几轮没暴露**：估算逻辑本身没有 bug（用户能看到"降级到纯图标"正是 row-icon / row-compact 也失败时返回 c 的字段对不上导致），加上我前几轮的判断只盯着"估算数值"和"渲染模式"，没去看"useMemo 返回值"是否真的会被消费。**TypeScript 不会报这种字段名不匹配的错**（解构 undefined 字段合法且无诊断），等于完全静默。

**修复**：
- `candidates` 类型与字段名改为 `{ mode, navLabel, callLabel }`，与外层解构严格对齐；
- `for` 循环内显式 `return { mode: c.mode, navLabel: c.navLabel, callLabel: c.callLabel }`；
- 兜底 `split` 也是 `{ mode: 'split', navLabel: '导航到店', callLabel: fullCall }`；
- 加一行注释提示字段必须对齐，避免再犯。

**校验**：`npx eslint --fix` + `prettier --write` + `rm -rf dist && VITE_USE_MOCK=true npm run build:weapp`（5.76s 通过）；产物关键字命中 `联系电话`×2、`导航到店`×2、`到店`×7、`免费试听`×1、`暑期特惠`×1。

**通用教训（写入七律）**：
1. **解构字段名必须与返回对象的字段名 1:1 对齐**——TS 类型不会因为"解构字段缺失"报错，等于一个隐蔽死代码陷阱。写 useMemo / 普通函数时，若返回对象字段名跟下游解构不一致，立即给 TS 加上显式返回类型或在调试时 console.log 一遍返回值。
2. **看到「永远/总是某种表现」时，第一反应去看"输入值是否真的传到了那里"**——别被"补偿式调参"（不断调估算常数）带偏。这次连续 4 轮我都只调估算参数、调 TAG_GAP_RPX、调 TEXT_FRIENDLY_MARGIN_RPX——本质都在改同一层，根本没碰到 bug 层。
3. **校验"真的改了"不能再只看产物关键字**——产物里 `\u8054\u7cfb\u7535\u8bdd` 一直在，但运行时取不到是另一回事。下次遇到"改完没生效"类反馈，先在调试时打印 `useMemo` 的返回值，再决定要不要重打包。
