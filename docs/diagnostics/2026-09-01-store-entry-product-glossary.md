## 1. 名词表（全局必须统一）

| 产品 / UI 用语 | 含义 | 代码对应（允许） | **禁止混用** |
|----------------|------|------------------|--------------|
| **管理员** | 对外 UI 主称谓：门店入驻获批后的机构拥有者 | `Organization.ownerId` + `OrganizationUser.role=OWNER`；`Profile.role=PRINCIPAL`（库占位，**不改枚举**） | 不要用「校长」指入驻创建人 |
| **机构管理员** | 文档长称，同「管理员」 | 同上 | — |
| **校长（校区角色）** | 某**校区**管理岗（邀请员工等） | `CampusRole` / 邀请 `campus_principal` 等 | **≠** 管理员 / OWNER |
| **门店入驻** | 申请开新机构的流程页 | `store-entry` | 不要写「免审独立创建」 |
| **运营审核** | Admin 批准/驳回，防泛滥 | `admin.store-entry` | 不要标「产品偏差」 |
| **演示机构** | 审核未通过前，让申请人先体验产品的公用样板店（种子常名「松果排课」） | demo org / `DEMO_ORG` / seed-demo-org | **自有机构生效后禁止再进** |
| **选择身份** | 注册/登录后必经分叉页：开店 or 加入已有店 | `identity-select` | 未完成前**强制停留**，不能先逛业务首页 |
| **绑定机构** | 选择身份上弹窗填一码加入别人的店 | 统一绑定 API；不跳页 | 不要再叫「只绑定学员」 |
| **学员码 / 员工码前缀** | 码开头：`S`=学员，`E`=员工 | 生成时带前缀 | 两种码不能长得一样 |
| **机构 id** | 这家店在系统里的身份证号 | `organizationId` | 禁止用店名、用户 id 冒充 |
| **登录凭证** | 登录后记得「你是谁、哪家店」 | token / JWT / 会话 | 无机构 id = 还不知道你属于哪家店 |
| **默认头像** | 未上传时的统一占位图（品牌 Logo） | `BRAND_LOGO` / `sgpk.png` / `resolveAvatarSrc` | 禁止问号、空图、首字色块当默认 |
| **缓存优先** | Tab/页面再进入时先用已有数据 | TTL + refresh signal | 禁止每次 `useDidShow` 无脑全量拉库 |
| **课表可见** | 谁能看哪些排课/消课 | PRINCIPAL=机构全部；TEACHER=本人；无权限=空 | 禁止失败页/失败 toast 当空态 |

机构之间：**按 `organizationId` 隔离**。  
后续必做：**一家机构多个校区**（模型已有；FREE 配额可仍为 1，注释勿写死「永久单校区」）。

### 默认头像（已拍板 · 全局）

| 场景 | 规则 |
|------|------|
| 机构 / 学员 / 员工 / 家长 / 班级等列表与详情 | **有上传 URL → 用上传的**；否则 → **`/assets/images/sgpk.png`** |
| 图片 404 / 加载失败 | 回落同一品牌图 |
| UI 禁止 | 空圆、问号图标、仅首字渐变色块冒充「默认头像」 |

前端入口：`constants/brand.ts` 的 `BRAND_LOGO`；统一解析 `utils/avatar-src.ts` 的 `resolveAvatarSrc`。

### 客户端拉数（已拍板 · 企业级）

| 触发 | 期望行为 |
|------|----------|
| Tab 来回切换 | **展示缓存**；距上次成功拉取未超过 TTL → **不发全量请求** |
| 下拉刷新 / 用户显式刷新 | 允许强制打接口 |
| 写操作成功（改课、消课、待办完成等） | 写 refresh signal 或局部更新，再进入页时刷新 |
| 冷启动 / 登录切换机构 / 换校区 | 允许全量拉取 |

**禁止**：每次 `useDidShow` 无条件 `loadData` / 月消课 / 调课列表全量查库（用户少也会被「点一下查一次」打成高峰）。

### 课表 / 消课可见范围（已拍板）

| 角色（产品） | 代码角色 | 可见数据 | 写权限 | 无数据 / 无权限时 |
|--------------|----------|----------|--------|-------------------|
| **管理员** / 校区**校长** | `PRINCIPAL`；机构 `OWNER`/`ADMIN` | **本机构全部**排课、班级、消课、临时调课 | **本机构可改**（代管他人班级/排课；排课归属仍记班级原教师） | **空列表 / 空白 UI** |
| **教师** / **助教** | `TEACHER` | **仅本人** | **仅本人** | 同上 |
| **家长** | `PARENT` | 绑定孩子相关 | 无教务写 | 同上 |
| 其他 / 未授权 | — | 无 | 无 | **空列表**；禁止失败页 / 失败 toast |

**禁止**：把管理员当成家长鉴权；管理员读课表**不得**强制先绑定教师档案；写操作时**不得**把他人班级的 `Schedule.teacherId` 改成管理员自己。

### 临时调课（已拍板 · 真联动）

| 课表 UX | 无审批弹窗 → **保存即 `approved` 生效** |
| UI | 本轮 **不改**课表页面结构；仅允许 service 适配器改逻辑 |

### 库 vs UI（已拍板）

| 层 | 取值 |
|----|------|
| DB `Profile.role` | 继续 `PRINCIPAL`（工程占位，不新增枚举） |

## 2. 两条合法路径（都要运营批准）

### 路径 A · 运营分享入驻页（获客）— **已拍板**

1. 运营分享门店入驻落地页。  
2. **未登录也可打开**：可预览页面、可填写表单；前端尽量暂存微信标识。  
3. 点击**提交申请**时：若无登录态 → **必须先登录**（登录后回跳，草稿保留）。  
4. **绑定邮箱**：用于收「审核通过」等通知；**软要求** — 可提示，用户可选 **「下次再说」**，**不硬挡提交**。  
5. 申请写入；机构可为 `PENDING`。  
6. **已申请、未批准**：登录后会话挂到**演示机构**，可先看演示效果（只读/受限以产品后续细化为准）。  
7. 运营 Admin **批准**后：机构 `ACTIVE`、申请人 = **管理员（OWNER）**、按表单建**默认主校区**；会话切到**自有机构**，**禁止再进入演示机构**。  
8. 后台续登录（刷新 token）：若已有正式机构 → **无感补上机构 id**，用户不用重登。

### 前端硬规定（已拍板）

登录 / 刷新后，前端存的「当前机构」**必须**来自登录结果里的真实 `organizationId`。  
**禁止**用机构名称、`profileId`、用户 id 等顶替（防串台）。

### 选择身份页（已拍板 · 强制）

注册 / 登录成功，且尚未完成「门店入驻申请或自有机构」也尚未「邀请码绑定进机构」时：

1. **强制停留在「选择身份」**，不能进首页（路由守卫要拦）。  
2. 两个主入口：  
   - **门店入驻**：管理员申请开自己的店（需运营审核）→ 进门店入驻页。  
   - **绑定机构**：**不跳转新页**，本页弹出**一个输入框**；用户只填一个码；**后端根据码的特征自动走学员绑定或员工绑定**。  
3. **未申请也未绑定**：就停在此页，**不**自动进演示机构。  
4. **已申请未批准**：走演示机构体验（见路径 A）；不是停在选择身份空转。  
5. 文案禁止再写「绑定学员」当主标题。

### 邀请码特征（已拍板）

| 类型 | 前缀 | 说明 |
|------|------|------|
| 学员邀请码 | **`S`** | 家长/学员绑定孩子进机构 |
| 员工/教师校区临时邀请码 | **`E`** | 员工加入校区（原 CampusInvite 生成须带此前缀） |

- 生成时写入前缀；校验时先看首字符分流（再查对应表）。  
- 选择身份「绑定机构」：弹窗只调**一个**统一校验/绑定接口。  
- 历史无前缀旧码：本迭代可兼容「无前缀先查员工再查学员」或提示重新发码——实现优先新码；旧码兼容策略由修会话选更稳的一种并写测。

### 路径 B · 自然量（自己打开小程序）

1. 注册 / 登录。  
2. **强制**进入选择身份。  
3. 选门店入驻 → 填表提交 → 未批进演示机构 → 批准后自有店。  
4. 或点绑定机构 → **弹窗输码** → 后端自动区分学员/员工并完成绑定。  

**无免审直开机构。**
