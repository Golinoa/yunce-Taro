## 一、两轮工作结论（先总后分）

| 轮次 | 焦点 | 结论一句话 |
|------|------|------------|
| **第一轮** | 原子页交互 × 前后端契约 | 主闭环（绑定机构、首页、班课约、请假提交、消课只读）可联调；约课四态/私教/场地/卡包/评价未真正打通 |
| **第二轮** | 路径百分百（入口+深链+断链+负向） | 注册页全覆盖后发现：认证遗留断链、资料页「添加子女」生产必失败、成长档案入口分裂、大量机构写页可深链越权 |

**产品总判**：家长端「能看见的入口」多于「能稳定完成的闭环」。演示/Mock 路径偏完整，真机生产路径存在多处「点得进去、办不成事」或「办成了但数据不落库」的预期落差。

## 二、核心用户流程梳理（应然 vs 实然）

### 流程 A：新家长入驻 → 绑定孩子 → 首页可用

| 步骤 | 用户操作 | 应然 | 实然（代码走查） |
|------|----------|------|------------------|
| 1 | 登录/注册 | 进入家长身份 | 邮箱码注册 → 引导链；遗留 role-select 断链 |
| 2 | 完善资料 | 填昵称头像 | profile-setup 存在 ✓ |
| 3 | 选身份 | 「我是家长/绑定机构」 | identity-select「绑定机构」✓；「门店入驻」随后会被权限拦回 |
| 4 | 输邀请码绑定 | 绑定孩子进首页 | parent-onboarding → organization/bind **已打通** ✓ |
| 5 | 确认关系 | 选父子关系 | RelationConfirmSheet ✓ |
| 备选 | 「我的」里再绑 | 同一套邀请码逻辑 | 走 mock bindParent，**生产失败** |
| 备选 | 点分享链接 | token 校验后绑定 | token 仅非空；绑定数 mock |

### 流程 B：看课表 → 约课 / 请假

| 步骤 | 用户操作 | 应然 | 实然 |
|------|----------|------|------|
| 1 | 金刚「我要约课」/ Tab 课表 | 看到孩子相关课 | 班课按绑定班级过滤 ✓ |
| 2 | 班课请假 | 提交请假申请 | leave-request 提交 **已打通** ✓ |
| 3 | 想调课 | 选目标课并提交 | **生产禁调课**（Toast）；Mock 可调但补课不落库 |
| 4 | 团课预约 | 约上/可在「我的课程」看到 | 后端约班课 ✓，同时写本地；「我的课程」**主要靠本地** |
| 5 | 私教约 | 选老师时段落库 | **只写本地**，换机即丢 |
| 6 | 场地约 | 选时预约成功 | 接口路径/权限全面错位，**不可用** |

### 流程 C：查课时 / 卡包 / 成长

| 步骤 | 用户操作 | 应然 | 实然 |
|------|----------|------|------|
| 1 | 「我的卡包」 | 看孩子课包剩余 | **跳到「我的课程」约课列表**（错链） |
| 2 | 「成长档案」 | 列表进详情看卡包出勤 | 列表**点不进详情**；卡包从首页课时区或资料页才能进 |
| 3 | 详情卡包 Tab | 看剩余课时 | 调教师专用课包接口 → **403** |
| 4 | 资料里「添加子女」 | 自助加孩子 | 走教师建档 API → **403**（应引导邀请码绑定） |
| 5 | 「我的」核心数据 | 出勤/剩余次数等 | **恒为 0** |

### 流程 D：作业 / 点评 / 评价

| 步骤 | 用户操作 | 应然 | 实然 |
|------|----------|------|------|
| 1 | 课后作业/课堂点评 | 列表 → 课节详情 | 读消课字段，路径通 ✓（依赖老师写入质量） |
| 2 | 上课记录 | 看全部孩子 | **默认只看第一个孩子**，无切换 |
| 3 | 待评价 → 提交 | 评价落库 | **模拟成功**；状态改回「已预约」，语义混乱 |

## 三、问题清单（按严重程度排序）

### P0 — 阻断主任务或造成严重预期落差

#### 1. 「看起来约成功了，其实没进系统」——私教约课 / 我的课程四态

- **环节**：课表私教 `from=parent`；「我的」→ 已预约/排队/待评价/已取消  
- **问题**：成功 Toast / 列表有数据，但真相源是本地缓存，无服务端聚合；换设备、清缓存、多端查看全部失效。团课虽打后端，仍双写本地，列表与真约可能不一致。  
- **用户影响**：以为约上了，到校发现未约；投诉、信任崩塌。  
- **建议**：以 class-booking（及未来私教约）为唯一真相；「我的课程」必须读服务端；本地仅作离线草稿并明示。上线前关闭或灰显私教自约，直到后端就绪。

#### 2. 「我的卡包」点进去不是卡包

- **环节**：我的 → 我的卡包  
- **问题**：入口文案承诺「卡包」，落地「我的课程」约课四态。  
- **用户影响**：找不到剩余课时，误以为没有课包或产品坏了；重复咨询前台。  
- **建议**：跳转 `child-detail?tab=packages`（多孩先选孩子）；无孩时引导绑定。同步修复卡包 Tab 的 PARENT 读权限（或改用详情内嵌课包）。

#### 3. 场地预约入口存在但办不成

- **环节**：课表 → 场地 → 确认预约  
- **问题**：前后端路径、字段、角色全面错位；家长无创建权限。  
- **用户影响**：填完表提交失败或无响应，流程空耗。  
- **建议**：产品决策是否开放家长场地自助；若开放，统一契约并对 PARENT 放行创建；若不开，家长端隐藏场地入口。

#### 4. 邀请/加孩子三条路，两条是死路

- **环节**：分享 parent-bind；成长档案复制邀请码；资料页「添加子女」；「我的」内绑定 Sheet  
- **问题**：  
  - 展示码为前端自造，无法用于真实 `organization/bind`；  
  - 分享 token 不校验；  
  - 「我的」绑定走 mock；  
  - 「添加子女」走教师建档接口 → 生产 403。  
  - **仅** onboarding 邀请码绑定可靠。  
- **用户影响**：家长按界面操作反复失败；配偶无法共享档案；客服解释成本高。  
- **建议**：全产品统一「机构学员邀请码绑定」一种叙事；去掉自造码与家长自建学员；分享须服务端签发一次性令牌；失败文案指向正确入口。

#### 5. 成长档案「进不去详情」+ 卡包 403

- **环节**：金刚「成长档案」→ 孩子列表；详情卡包 Tab  
- **问题**：列表无进详情；详情卡包接口对家长禁权。首页课时区 / 资料页却可进详情 → 路径分裂。  
- **用户影响**：以为成长档案只能看列表；从「正确」入口反而看不到卡包。  
- **建议**：列表卡片点击进详情；卡包数据用详情已下发的课包或开放 PARENT 只读；三条入口（档案/课时/资料）信息架构对齐。

### P1 — 明显伤体验，但不一定阻断全业务

#### 6. 「我的」核心数据全是 0

- **环节**：我的页四列统计  
- **问题**：累计出勤/剩余次数等硬编码 0，像已上线空壳。  
- **影响**：家长认为没消课或系统不准。  
- **建议**：接真实聚合或未就绪时隐藏该区块，勿展示假 0。

#### 7. 多孩场景缺切换——上课记录只看老大

- **环节**：上课记录 / 默认拉数  
- **问题**：无学员筛选，默认第一孩；作业点评虽聚合多孩，记录页不聚合。  
- **影响**：二孩家长漏看记录，以为没课。  
- **建议**：顶栏孩子切换；默认「全部」；与作业页行为一致。

#### 8. 请假叫「请假调课」，生产只能请假

- **环节**：金刚文案 / 申请类型  
- **问题**：名称承诺调课；真机点调课被 Toast 拒绝；Mock 又可调。演示与真机双标。  
- **影响**：觉得功能忽有忽无、不专业。  
- **建议**：生产文案改为「请假」；或完成调课+补课后端后再开放；帮助页说明差异。

#### 9. 待评价「提交成功」但不落库，状态还改乱

- **环节**：我的课程 → 待评价 → 评价弹层  
- **问题**：模拟提交；条目变回「已预约」。  
- **影响**：以为评过了，列表行为诡异。  
- **建议**：未接 API 前隐藏「去评价」或标明「即将上线」；接 API 后状态应为「已评价」。

#### 10. 占位功能仍占宫格（排行榜 / 积分 / 帮助空壳）

- **环节**：我的服务区；使用帮助  
- **问题**：点击 Toast「开发中」；帮助「内容待填充」。  
- **影响**：削弱对真实功能的信任。  
- **建议**：未上线入口不下发或收纳到「更多-即将推出」；帮助至少放 FAQ（绑定/请假/约课）。

### P2 — 摩擦、冗余、反馈与边界

#### 11. 绑定孩子入口过多且规则不一

- **环节**：onboarding / 我的 Sheet / parent-bind / 资料添加子女 / 邀请码复制  
- **问题**：步骤不冗余在「次数」，而在「规则不一致」——用户不知哪条有效。  
- **建议**：主路径只留「输入机构邀请码」；其余入口收敛到同一 Service 与同一失败提示。

#### 12. 身份切换 Sheet 做了但打不开

- **环节**：首页/我的 RoleSwitchSheet  
- **问题**：多身份家长无法从主界面切换（仅深链 role-switch）。  
- **影响**：兼职家长/老师身份切换路径缺失。  
- **建议**：在「我的」头像区提供明确「切换身份」；或删掉死组件避免维护幻觉。

#### 13. 异常与边界反馈偏弱

| 场景 | 现状 | 建议 |
|------|------|------|
| 卡包 403 | 易表现为空或笼统失败 | 明确「暂时无法查看课包，请联系机构」 |
| 添加子女失败 | 泛化「添加失败」 | 引导「请使用机构提供的学员邀请码绑定」 |
| 场地提交失败 | 契约错误，提示不可预期 | 隐藏入口或统一错误页 |
| 无绑定孩子约课 | 部分有 Toast | 统一空态：插画 +「去绑定」主按钮 |
| 邀请码错误 | onboarding 笼统检查提示 | 区分：码无效 / 已绑定 / 网络错误 |

#### 14. 认证与断链边角

- **环节**：找回账号/联系客服页无入口；遗留注册选角色链断开；选「门店入驻」被拦回首页  
- **影响**：少数用户卡住或摸不着门。  
- **建议**：补齐客服入口或下线路由；identity-select 对已是家长的用户弱化/隐藏门店入驻；清理遗留注册页避免运营误导。

#### 15. 安全与信任（产品侧可见后果）

- **环节**：深链进入消课/充值/操作日志等机构页  
- **问题**：入口藏了但守卫不全 → 懂行用户或分享链接可进。  
- **影响**：误操作风险、合规与机构信任问题。  
- **建议**：凡 Staff 写操作页一律角色守卫；家长误入给出「这是老师功能」说明并回首页。

## 四、流程层面的结构化观察

| 观察维度 | 判定 | 说明 |
|----------|------|------|
| 流程是否顺畅 | **主线尚可，支线断裂** | 绑定→首页→班课请假较顺；卡包/私教/场地/评价支线断裂 |
| 步骤是否冗余 | **中等** | 绑定入口过多造成认知冗余，而非点击步数过多 |
| 步骤是否缺失 | **明显** | 缺：多孩切换、真实评价、调课闭环、卡包正确落地、身份切换入口 |
| 异常/边界 | **不足** | 403/空数据/Mock 分叉缺少产品级文案与降级 |
| 反馈是否清晰 | **部分虚假反馈** | Toast「成功」但未落库；统计「0」像真实数据 |
| 预期 vs 实际 | **多处不一致** | 卡包错链、请假调课名实不符、成长档案点不进、添加子女失败 |

## 五、优化优先级建议（产品排期口径）

1. **立刻修文案与跳转（低成本高感知）**：卡包入口、请假文案、隐藏未上线宫格、隐藏/降级私教与场地自约、隐藏假 0 统计。  
2. **打通「孩子与课包」真相**：真实 inviteCode、统一绑定、列表进详情、卡包只读、去掉家长 create student。  
3. **约课闭环**：我的课程读服务端；私教约后端化或下线；取消双写漂移。  
4. **多孩与记录**：记录/作业统一孩子筛选。  
5. **守卫与信任**：Staff 页角色拦截；失败提示产品化。  
6. **评价/调课/积分**：作为二期能力，未就绪不露入口。

## 六、两轮结果对照摘要

| 主题 | 第一轮（契约/页面） | 第二轮（路径穷尽） | 产品合并结论 |
|------|---------------------|--------------------|--------------|
| 绑定 | onboarding 已打通；Sheet/bind mock | 认证树完整；添加子女 403；断链注册页 | **只保留邀请码绑定一种主路径** |
| 约课 | 班课通、私教/四态本地、场地错位 | 跳转树确认入口齐全但闭环不全 | **入口收缩到已打通能力** |
| 成长/卡包 | 卡包 403、错链 | children 与 profile-edit 路径分裂 | **信息架构统一 + 权限** |
| 安全 | hideForParent ≠ 守卫 | 123 页标出 P-深链全集 | **按矩阵补守卫** |
| 覆盖度 | 主入口原子页 | 123/123 + 24 步冒烟 | **可用性以「闭环」而非「能打开页」验收** |
