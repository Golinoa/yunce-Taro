## 1. 已排除清单（勿重走）

- **已排除：订阅弹框宿主未挂载。** `SubscribeAuthHost` 挂在 `src/app.tsx:127`（`AuthProvider` 内、`props.children` 同级），全局可用，不依赖具体页面。
- **已排除：`getFlowPresetId('E01'/'E11')` 无预设导致早退。** `constants/subscribe-presets.ts:296,303` 明确映射 `E01 → student_created`、`E11 → teacher_created`，两条分支都会进入 `openPrompt`。
- **已排除：接口/数据层问题。** 三条链路的后端写入均成功（记录已落库、列表能看到新增数据），故障纯在前端「保存成功之后」的反馈与导航编排。

## 2. 硬约束（下一轮开工前必读）

1. **不要在 `Taro.showToast` 之后立刻调 `Taro.hideToast()`。** 那等于提示白弹。若担心 toast 挡住后续 modal，正确做法是**等 toast 自然播完（1500ms）再 hide + showModal**——原因见根因 2 的时序说明。
2. **不要让 `await subscribeMessageService.runFlow(...)` 挡在跳转之前。** `runFlow → openPrompt`（`src/stores/subscribe-auth.ts:57`）返回的 Promise **只在用户点击订阅弹框（`closePrompt`）时才 resolve**。一旦弹框未被点击/未渲染，Promise 永久 pending，后续代码永不执行。必须 `void runFlow(...)` fire-and-forget。
3. **回列表统一走 `backToListPage(listPath)`**（`src/utils/post-save-navigation.ts`），它会按页面栈算出 delta 一次退到底，栈内无列表页时 `redirectTo` 兜底。原 `venue-form` 的私有 `goBackToList` 已收敛到该工具，勿再各页重写。
4. 统一延时用 `SUCCESS_TOAST_MS`（=1500，与 `Taro.showToast` 默认时长一致），不要再写 400 / 800 这类魔法值。

## 3. 现象与代码证据

### 场地 `package-settings/pages/venue-form/index.tsx`
```ts
Taro.showToast({ title: '保存成功', icon: 'success' });
setTimeout(goBackToList, 400);   // ← 400ms 就退栈，短于 toast 1500ms
```
提示存在但一闪即被 `navigateBack` 带走的页面一起清掉，用户观感 =「点保存直接回列表」。

### 员工 `package-teacher/pages/teacher-form/index.tsx`
```ts
Taro.showToast({ title: '添加成功', icon: 'success' });
try {
  Taro.hideToast();                              // ← 立刻抹掉成功提示
  await subscribeMessageService.runFlow('E11');  // ← 可永久 pending
} catch (e) { logError(...) }
...
setTimeout(() => Taro.navigateBack(), 800);      // ← 在 await 之后，被卡住
```

### 学员 `package-student/pages/student-form/useStudentForm.ts`
```ts
Taro.showToast({ title: '学员已创建', icon: 'success' });
...
void (async () => {
  Taro.hideToast();                              // ← 立刻抹掉成功提示
  try { await subscribeMessageService.runFlow('E01'); } catch { ... }
  const { confirm } = await Taro.showModal({ title: '学员已创建', ... });  // ← 被卡在这一步之前
  Taro.navigateTo(...);                          // ← 永不执行
})();
```
**这一条完整解释了用户现象**：`hideToast()` 吃掉提醒；`await runFlow()` 一旦不 resolve，「是否立即发会员卡」弹窗与后续 `navigateTo` 全都不会执行 = 也没有跳转。

## 5. 改动

新增 `src/utils/post-save-navigation.ts`：
- `SUCCESS_TOAST_MS = 1500`
- `askContinueCreate(subject)`：等 toast 播完 → `hideToast()` 兜底 → `showModal('是否继续新增X？')` → `true`=继续 / `false`=返回列表
- `backToListPage(listPath)`：精确退栈到列表页，兜底 `redirectTo`

三处调用点统一为：
```
保存成功 → Taro.showToast('成功') → setRefreshSignal(如有)
  ├─ 编辑态：setTimeout(navigateBack / goBackToList, SUCCESS_TOAST_MS)
  └─ 新增态：await askContinueCreate(X)
               ├─ true  → 重置表单留在本页（学员额外恢复默认主校区）
               └─ false → backToListPage(列表路径)
             随后 void runFlow(...)（fire-and-forget，不阻塞）
```

按用户决策（2026-09-25）落地：
- 三条链路**统一回列表**语义；学员**去掉**「是否立即发会员卡」弹窗与跳转（不再跳会员卡页/学员详情）。
- 场地/员工新增成功后**增加**「是否继续新增？」询问，便于连续录入。
