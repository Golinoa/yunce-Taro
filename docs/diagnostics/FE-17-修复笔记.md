## 2. 下一轮开工前必读（硬约束）

1. **只有 `border-style: solid` 而没有显式宽度 = 四边全画**。CSS 中 `border-width` 的初始值是
   `medium`（≈3px），不是 0。默认不显示只是因为 `border-style` 初始值是 `none`。
   一旦 `border-solid`（UnoCSS 只输出 `border-style:solid`）和 border-color 同时出现在元素上，
   **四条边都会以 3px 出现**，哪怕你只给某一边写了宽度。
2. **必须一次给全四边的 width / style / color**：
   - ❌ `border-l-[1rpx] border-solid border-destructive`
   - ❌ `border-[1rpx] border-solid border-destructive`（`border-[1rpx]` 只给宽度，style 靠 `border-solid`，仍有其它边风险）
   - ✅ `border-left: 1rpx solid hsl(var(--destructive))`（单边形态）
   - ✅ `border: 1rpx solid hsl(var(--destructive))`（**整圈形态，本项目最终采用**，
     封装为 `border-status-danger` / `border-status-warn`）
3. **`border-t` 是安全的**（`uno.config.ts` 里自带 `border-top-style: solid`），但它**不能**和
   `border-solid` 挂在同一个元素上 —— 那会让其余三边回退成 3px，复现同一个 bug。
4. 铁律（沿用 FE-16）：**改样式必须核对产物 wxss**，不能只看源码：
   `grep -o "\.[A-Za-z0-9_-]*{[^}]*border[^}]*}" dist/app-origin.wxss`，
   并且要**同时确认旧类从产物 js 里消失**（说明没有元素再挂旧组合）。

## 3. R1（buildId `students-debug-20260923-07`）

**② 现象**（用户 2026-09-23 19:23 原话 + 截图）：

> 「学员信息边框的粗细没有变化 你调整一下我要细的线条」

截图：学员管理页「共 4 位学员」，每张卡片四周均为**红色圆角边框**，粗细约 3px，四边均匀。

**③ 假设**：边框过粗是因为宽度写成了 `3rpx`（=1.5px），改成 `1rpx`（≈0.5px）即可。

**④ 验证方式**：`utils/hours-status.ts` 的 `getCardBorderColorClass` 把 `border-l-[3rpx]` 改为
`border-l-[1rpx]`（红/黄两处），编译 + 核对产物。

**⑤ 结论**：**不成立（根因判断错误）**。
产物里 1rpx 的 CSS 确实生成了（见排除清单），但用户复看后反馈**完全没有变化**。
⇒ 控制视觉粗细的**不是这条声明**。

**⑥ 改动文件**：`src/utils/hours-status.ts`（`3rpx → 1rpx`，仅此一处）。

**⑦ 验证结果**：产物含 `.border-l-_a_1rpx_a_{border-left-width:1rpx}`；但**用户侧视觉无变化** ⇒ 失败。

## 4. R2（buildId `students-debug-20260923-09`）—— 找到真根因

**② 现象（原始观测数据）**：

1. 截图显示卡片是**四边**红框，粗细均匀；但源码里该元素**只有 `border-l-*`（左边）**。
   → 「只有一条边的声明」和「四边都有框」自相矛盾，这本身就是最强线索。
2. 产物 `dist/app-origin.wxss`（`-08`，编译于 16:25）相关规则全文：

   ```
   .border-solid{border-style:solid}
   .border-l-_a_1rpx_a_{border-left-width:1rpx}
   .border-destructive{...}   ← border-color，作用于四边
   ```

   全产物中 `border-width` / `border-top-width` / `border-right-width` / `border-bottom-width`
   相关声明**没有任何一条**指向这个卡片的元素 ⇒ 那三边的宽度**不是本项目写的**。

**③ 假设**：CSS 规范中 `border-width` 的**初始值是 `medium`（≈3px）**，默认不显示只是因为
`border-style` 初始值是 `none`。一旦 `border-solid` 把 `border-style` 变成 `solid`：

- `border-left-width` = `1rpx`（显式声明）
- `border-top/right/bottom-width` = **`medium` = 3px**（回退到初始值）

再叠加 `border-destructive` 的四边颜色 → **整圈 3px 粗红框**。
而左边那条 1rpx 被夹在三条 3px 线之间，**改它当然看不出变化**。

**④ 验证方式**：
1. 用 CSS 规范核对「`border-width` 初始值 = `medium`(=3px)、`border-style` 初始值 = `none`」；
2. 在产物 wxss 里反证：确认**没有**任何规则给上/右/下三边写过宽度（若不是初始值回退，
   必然能在产物里找到来源）；
3. 视觉吻合：截图缩放比约 1.53×（375 逻辑宽），3px 逻辑宽 ≈ 4.6 截图像素，与截图边框粗细一致。

**⑤ 结论**：**技术根因成立**（三条独立证据一致）；但**目标形态判断错误** —— 见 R3。

**⑥ 改动文件**：

- `uno.config.ts`：新增两条规则（放在「===== 边框 =====」区块），并写明为何不能拆写：
  ```ts
  ['border-l-status-danger', { 'border-left': '1rpx solid hsl(var(--destructive))' }],
  ['border-l-status-warn',   { 'border-left': '1rpx solid hsl(var(--warning))' }],
  ```
- `src/utils/hours-status.ts`：`getCardBorderColorClass` 返回值改为上述两个类。
- `src/utils/local-debug.ts`：`DEBUG_BUILD_ID` → `students-debug-20260923-09`。

**⑦ 验证结果**：

- 产物已生成 `.border-l-status-danger{border-left:1rpx solid hsl(var(--destructive))}` 等两条。
- **旧组合从学员页产物 js 中彻底消失**：`border-destructive` / `border-amber` /
  `border-solid` / `border-l-[1rpx]` 全部不再出现（此前四个都在）。
- 主包 1483.2KB / 1536KB；129 页 0 缺失；共享模块校验 21 个通过。
- 门禁：`tsc` 0 错 / `eslint` 0 error / `prettier` 通过 / `vitest` **130 文件 685 用例全绿**。
- **用户复看后的反馈：不是要左侧单线，是要整圈** → 触发 R3。

## 5. R3（buildId `students-debug-20260923-10`）—— 需求澄清，改为整圈

**② 现象**（用户 2026-09-23 21:00 原话，仅此一句）：

> 「我要的是整圈  原本就是整圈的」

**③ 假设**：R2 的技术根因完全正确，但**形态做错了**。需求从头就是**四边整圈**的状态色边框，
只是被「`border-style` 单独设置」的缺陷撑成 3px 粗框。目标 = **整圈 + 细（1rpx ≈ 0.5px）**。

**④ 验证方式**：改为 `border` 一体化简写 —— 一次给全四边的 width / style / color，
任何一边都不会回退到 `medium`；编译后核对产物，并确认学员页不再挂 `border-solid`。

**⑤ 结论**：**成立**（属需求澄清，技术结论承接 R2，全部保留有效）。

**⑥ 改动文件**：

- `uno.config.ts`：`border-l-status-danger|warn` → **`border-status-danger|warn`**，
  内部由 `border-left: 1rpx solid …` 改为 **`border: 1rpx solid …`**（整圈）。
- `src/utils/hours-status.ts`：`getCardBorderColorClass` 返回值同步改名，注释同步。
- `src/utils/local-debug.ts`：`DEBUG_BUILD_ID` → `students-debug-20260923-10`。

**⑦ 验证结果**：见下节。

## 6. 最终形态与验证

**形态**：学员卡片 = **四边整圈** `1rpx`（≈0.5px）状态色细边框，
红 = 无可用课包（`border-status-danger`），黄 = 即将到期 / 课时不足（`border-status-warn`），
正常态无边框。

**产物核对（铁律）**：
- `dist/app-origin.wxss` 生成
  `.border-status-danger{border:1rpx solid hsl(var(--destructive))}` /
  `.border-status-warn{border:1rpx solid hsl(var(--warning))}`。
- 学员页产物 js 中 `border-l-status-*`、`border-solid`、`border-destructive`、`border-amber`
  **全部消失** ⇒ 无任何元素再使用「单独 border-style + 四边 color」的危险组合。
- 主包体积、页数校验、门禁（tsc / eslint / prettier / vitest）结果见台账 FE-17 与本文 R2 第 ⑦ 段。
