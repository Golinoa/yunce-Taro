# Batch 5 真机验收路线

候选包：执行 Batch 5 时生成的 `dev-*` 构建；验收前由 reviewer 填入最终 Taro SHA、后端 SHA、后台 gitlink、日期和环境。

请使用真实微信开发者工具预览或实际测试设备，清空本机缓存后执行。每一步记录 tester、日期、设备/网络、候选 SHA、实际结果和截图/录屏路径；任何失败都记录阻断原因，不要用预览成功代替业务结果。

1. 使用测试账号登录，切换到“松果排课-演示店”，确认机构和门店名称正确；切换到另一机构后确认列表、缓存和详情不回填演示店数据。
2. 在运营后台和小程序分别打开课程分类、课程模板和课表，创建或编辑一条隔离测试记录，刷新和重新进入后确认名称、教师、时间和状态一致；用无权限账号验证写入被拒绝。
3. 打开学员详情，新增、编辑、删除一条跟进记录，刷新后确认操作人、学员和机构一致；使用另一机构 ID 验证读取被拒绝。
4. 打开卡种管理和售卡入口，创建隔离测试卡种并售卡，核对实际销售员工、金额单位、剩余课时和会员卡详情；执行冻结/解冻及允许的退款/冲正路径，确认调整审计可回显。欠课入口按当前真实成功或明确失败契约记录，不把空结果当成功。
5. 打开教师薪资规则，核对月份、底薪、课时费、提成、扣款/补发和复制规则；生成 pending 工资后核对 breakdown 可加总，确认/发放后重新进入确认金额不回退，工资条发送若未配置真实通道必须显示真实失败。
6. 清除小程序缓存并换设备重新进入，确认机构、课程、学员、会员卡和薪资页面从服务端恢复；切机构后再次确认旧机构数据不残留。
7. 记录每项预期、实际、证据路径和阻断项，回填现有 `device-walkthrough-record.json`。空记录、代填、只记录页面打开或只记录二维码预览均判定 No-Go。
