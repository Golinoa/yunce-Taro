| 项 | 结论 |

## 1. 数据链路与证据

1. **软删除只改状态、不删行**
   `use-student-detail-actions.ts:73-95` → `studentService.remove(id)` → `del('/students/:id')`，
   注释明确「软删除：调用后端删除接口（status → INACTIVE）」。
   确认弹窗原文也是「删除后学员**不再显示在在籍列表**，历史记录将保留」——**产品意图本来就是不显示**。

2. **后端列表接口带不回状态过滤**
   `services/student.ts:213-231` `getPageByTeacher` 只传 `page / pageSize / campusId / keyword`，
   **没有 status 参数** → 后端返回什么前端就收什么，INACTIVE 行也在其中。

3. **状态映射已把软删除标出来，但没人用**
   `services/student.ts:110-114`：
   ```ts
   const mapBackendStudentStatus = (status?: 'ACTIVE' | 'GRADUATED' | 'INACTIVE'): Student['status'] =>
     status === 'ACTIVE' ? 'active' : 'deleted';
   ```
   `types/student.ts:29` 的 `Student.status?: 'active' | 'deleted'` 就是为它准备的。

4. **主列表没有过滤（缺陷）**
   `students/index.tsx:391-394`（修复前）：
   ```ts
   const pagedStudents = useMemo(
     () => studentsQuery.data?.pages.flatMap((page) => page.list) ?? [],   // ← 全部照单渲染
     [studentsQuery.data],
   );
   ```
   而 `children/index.tsx:50`、`profile-edit/index.tsx:317` **都写了** `filter(s => s.status !== 'deleted')`。
   → 同一个约定，两处遵守、主列表遗漏，属明确的实现不一致。

## 2. 已排除清单（勿重走）

- **已排除：删除接口没生效。** 用户侧无「删除失败」toast，且删除后详情页数据消失；后端确实置了 INACTIVE。
- **已排除：列表返回后没刷新。** `use-student-detail-actions.ts:88` 会 `setRefreshSignal(REFRESH_SIGNAL.students)`，列表
  `students/index.tsx:451-459` 的 `useDidShow` 消费该信号并 `invalidateQueries({queryKey: ['students', kind, actorId]})`；
  实际 queryKey 是 5 元组 `['students', kind, actorId, campusId, keyword]`，**前缀匹配成立**（v5 默认 `exact:false`），失效会触发重拉。
- **已排除：路由向导拦不住**（本问题与路由无关，记录以免误判）。

> ⚠️ **注意二者的依赖关系**：过滤是「渲染前剔除」，失效重拉是「拿到新数据」。
> 缓存里那条旧数据的 `status` 仍是 `'active'`（删除前拉的），**所以过滤必须配合重拉才生效**。
> 本次两条链路都成立，故修复有效；若后续出现「删除后仍显示」，应先查信号是否被消费掉，而不是再加过滤。

## 3. 改动

export function isActiveStudent(student: Pick<Student, 'status'>): boolean {
  return student.status !== 'deleted';

## 4. 遗留与建议

1. **分页口径**：客户端过滤后 `pagination.total / totalPages` 仍含已删除学员，
   若某页被删空会出现「该页显示空但这页仍占一页」。属于客户端过滤的固有取舍
   （`children` / `profile-edit` 同样如此）。**更彻底的解法是后端让 `GET /students` 默认排除 INACTIVE**
   （或前端显式传 `status=ACTIVE`）——按 AGENTS.md「后端优先适配现有前端」，建议作为后续项与后端确认，
   本次未擅自改接口契约。
2. **`GRADUATED` 也被归为 `'deleted'`**：`mapBackendStudentStatus` 里非 ACTIVE 一律 → `'deleted'`，
   因此「已毕业」学员在主列表也会被一并隐藏。当前与另两处口径一致，但语义上「毕业」≠「删除」。
   是否需要区分（例如仅在「全部/毕业」子 Tab 展示），需产品确认，本次未改以免扩大影响面。
