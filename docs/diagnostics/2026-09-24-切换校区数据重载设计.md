# 切换校区 → 全量按校区重载数据（设计与实施）

日期：2026-09-24
范围：yunceTaro 前端（后端接口已具备 campusId 过滤能力，本次未改后端）

## 一、问题现象

切换校区后，多数列表仍是旧校区数据。

## 二、根因（调查结论）

1. **两个校区来源并存**
   - `useCampusStore.currentCampusId`：用户在校区弹窗里选的（持久化）
   - `profile.currentContext.campusId`：登录身份自带的归属校区
   切校区只改前者；大量取数代码用后者，或干脆不传。

2. **后端回落身份校区**
   student / class / lead / schedule / statistics / home / data-center 等列表接口都支持
   `campusId` 过滤，但不传时回落 `req.user!.campusId`（身份校区）。
   → 前端不显式传 campusId，切校区在后端视角等于没发生。

3. **两层缓存都可能有残留**
   - zustand 领域缓存：`resetDomainCaches('campus')` 会清（OK）
   - TanStack Query：之前 `queryClient` 在 `app.tsx` 内部 `new`，外部拿不到实例，清不掉

4. **页面级加载不依赖校区**
   例：首页今日课表 `useEffect(..., [profile])`，切校区不触发重载。

## 三、设计规范（全站统一四层）

| 层 | 规则 | 落地方式 |
|---|---|---|
| L1 单一取值 | 全站按校区取数只用 `useCurrentCampusId()`（选中校区 ?? 身份校区） | `src/hooks/use-current-campus-id.ts` |
| L2 缓存键含校区 | TanStack `queryKey`、zustand `cacheKey` 必须包含校区 | students queryKey、lead store cacheKey |
| L3 取数显式传校区 | 列表 service 调用一律传当前校区 | students / leads / classes / trial-slot 等 |
| L4 切校区即失效 | `resetDomainCaches('campus')` + `queryClient.invalidateQueries()` | `utils/reset-domain-caches.ts` + `utils/query-client.ts` |

## 四、已实施

1. `src/utils/query-client.ts`（新增）：全局 QueryClient 单例，`app.tsx` 注入同一实例
2. `resetDomainCaches`：补 `queryClient.invalidateQueries()`，TanStack 缓存一并失效
3. `src/hooks/use-current-campus-id.ts`（新增）：L1 唯一取值入口
4. 学员列表：queryKey + 请求参数改用统一校区；queryKey 变化即自动重拉
5. 线索：`leadService.getLeadCards(teacherId, tab, campusId)`；`useLeadStore.fetchCards` 缓存键加校区维度；学员页线索 Tab 传参并在切校区时重载
6. 课程表单 / 上课表单：学员列表、班级列表显式传当前校区
7. 试听时段配置：5 处身份校区改为统一校区
8. 首页落地页：今日课表加载依赖加校区，并把校区传给 `getTodaySchedules`

## 五、验证

- `tsc --noEmit`：0 错误
- vitest：campus-load(8) + students-query-gate + refresh-signal 共 12 passed
- dist 重建：`https://dev.chancore.cn/api/app/v1`，共享模块与 129 页面校验 PASS

## 六、遗留（未改，需确认后处理）

- 统计页（statistics）前端 service 未带 campusId，后端按身份校区返回
- 其余约 30 处 `profile.currentContext.campusId` 多为权限/身份判定或表单默认值，
  按《角色业务边界》不随切校区改变；如产品要求某页面跟随切换，按 L1–L3 逐页改造即可
