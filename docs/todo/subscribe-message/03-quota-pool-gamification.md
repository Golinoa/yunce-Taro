## 1. 两类提醒，两套策略

| 类型 | 谁触发 | 额度从哪来 | 到点没额度怎么办 |
|------|--------|------------|------------------|
| **自定义待办** | 用户设了 `remindAt` | 创建保存点击链申请 | 页内待办 + 参与人进站弹框 E13 |
| **系统规则提醒** | 后端 cron / 业务事件 | 业务成功 **弹框** + 操作后续 **弹窗** + pending 队列 | 站内 + E14/E15 |

**逐步链路定稿** → [04-event-role-flows.md](./04-event-role-flows.md)（弹框=Dialog 居中，弹窗=BottomSheet 自下而上）。

**系统提醒不靠「到点逼用户弹订阅」**——那是骚扰。正确路径：

```
创建学员 / 发卡 / 建线索 / 建教师  → 预囤对应模板额度
每次业务操作成功               → 「续下一次」轻引导（可跳过）
用户进小程序                   → 检测额度池，不足时委婉补囤
额度耗尽且功能仍开着           → 站内问「还要我继续提醒吗？」→ 引导去囤额度页
```

## 2. 系统提醒 · 预囤与续杯矩阵

> **预囤**：实体创建成功页/Sheet 上一次性申请（打包 ≤5 模板）。  
> **续杯**：该实体后续每次关键操作后，成功 Sheet 上「为下次提醒续一次」。

| 系统场景 | 预囤时机（首次） | 续杯时机（每次操作后） | 模板组 | 接收人 |
|----------|----------------|------------------------|--------|--------|
| 课时不足 | 添加学员成功 | 发卡、充值、点名后（家长侧） | `package_alert` | 顾问 + 家长 |
| 课包到期 | 添加学员 / 充值成功 | 充值成功、编辑课包有效期 | `package_alert` | 顾问 + 家长 |
| 上课提醒 | 家长绑定孩子 | 家长每次进小程序额度检测、上完课正向弹窗 | `class_remind` | 家长 |
| 点名结果 | 家长绑定孩子 | 每次上完课「真棒」续杯 | `lesson_result` | 家长 |
| 薪资单 | 创建教师 | 核对工资、发送工资单各续一次 | `todo_remind` | 教师本人 |
| 未点名 | 创建班级 / 首次排课 | 每次点名提交后续 `todo_remind` | `todo_remind` | 任课教师 |
| 调课停课 | 创建班级 | 排课保存、调班确认后 | `schedule_change` | 家长 + 教师 |
| 线索跟进 | **创建线索** | 每次添加跟进记录 | `todo_remind` | 顾问 |
| 协作待办 | 创建人保存 | 参与人打开待办详情 | `todo_remind` | 创建人 + **所有参与人** |
| 管理层风控 | 校长/顾问登录后囤额度页 | 看数据中心、发薪、跨科目事件后 | `todo_remind` + `approval_result` | 校长/顾问本人 |

### 2.1 协作待办（已定）

- **到点：所有参与人都发**（正常设计）。
- 某参与人 `remain=0` → 仅该人站内兜底（待办 + 进小程序弹窗见 §4）。
- 创建人只攒**自己的**额度；不参与替参与人授权。

### 2.2 管理层提示「没法替下属授权」怎么解

| 能做的 | 不能做的 |
|--------|----------|
| 校长/顾问在**自己设备**上囤 `todo_remind`、`package_alert`、`approval_result` | 替任课教师攒「未点名」额度 |
| 跨科目消课、校区续费预警 → 发给**已囤额度的校长** | 校长点一下就给老师加额度 |
| 教师长期 `remain=0` → 站内待办给校长「某老师多次未收到微信提醒」 | 强制教师弹订阅 |
| 教师进小程序 → 教师自己的弹窗 + 囤额度页 | — |

**管理层专属触点**：创建线索、添加学员、充值/发卡成功、核对并发送工资、打开数据中心 — 均走「续下一次」+ 囤额度入口。

### 2.3 `package_alert` 分期判断（技术拍板）

| 阶段 | 内容 |
|------|------|
| **Phase 1（跟基础设施一起）** | MP 申请 `package_alert` 模板；bootstrap 下发；**预囤/续杯触点**接在添加学员、发卡、充值；囤额度 UI 可囤该组 |
| **Phase 2** | 后端 cron：课时不足扫描、课包到期 7/3/1 天 **实际 send** |
| 理由 | 触点与模板申请一次做完；发送逻辑依赖配额表，可晚一周 |

## 3. 额度池检测 · 进小程序时做什么

### 3.1 检测时机（委婉，非逼迫）

| 时机 | 形式 | 频率上限 |
|------|------|----------|
| `app.onShow` / 首页 `useDidShow` | 拉 `GET /subscribe-message/quotas` | 每次冷启动 1 次 |
| 某组 `remain ∈ [1, lowThreshold]` | **横幅** E16 | 同组 24h 最多 1 次 |
| 某组 `remain === 0` 且开关仍开 | **弹框** E18 额度不足 | 同组 7 天最多 1 次 |
| 额度为 0 且 14d 无成功 send | **弹框** E15 再激活 | 14 天 1 次 |

### 3.2 家长端闭环（已定方向）

```
绑定孩子 → 立刻预囤 class_remind + lesson_result + package_alert（最多 5 个）
每次上课后 → 正向弹窗续 lesson_result / class_remind
进小程序 → 检测池子；不足则横幅「提前囤几次提醒更安心」
拒绝 → 仅站内；7 天后再激活问一次
```

### 3.3 教师端 · 任课教师不在操作现场

操作者 `OP` 添加学员/入班时，**任课 `HT`、助教 `AT`** 若不在现场：

1. 后端写 `pending_subscribe_prompt`。
2. 教师下次进站 → **弹框** E02-B：「学员已加入您任课的班级，是否订阅任课提醒？」
3. 点 [订阅提醒] → 微信订阅面板 → [查看班级] → 班级页 **弹窗** E02-D 再屯 1 次。

教师点名后 → **弹窗** E05 每次屯；未收到微信 → **弹框** E14 → 查看班级 → **弹窗** E02-D。

完整逐步说明见 [04-event-role-flows.md](./04-event-role-flows.md)。

## 4. 协作待办 · 参与人进小程序

**不用**冷启动就弹微信订阅（不合适）。

```
参与人有新协作待办
  → 后端写站内 + pending collab_todo_new
  → 进小程序：**弹框** E13「你有新的待办：{标题}」[稍后] [查看待办]
  → 点 [查看待办] → 详情（不调 subscribe）
  → 详情 [开启到时提醒] → 用户点击 → 微信订阅
```

## 5. 囤额度玩法 · 日历铃铛 + 敲木鱼

> 参考：Readhub 早报「点 +1 屯额度」、电子木鱼「功德 +1」——把**无聊点击**变成**攒通知次数**。

### 5.1 产品形态

**入口**：消息通知页底部 · 我的页 · 额度不足横幅 · 授权成功 Sheet 次要按钮「去屯点额度」。

**页面结构**（`package-settings/pages/quota-pool` 或独立分包页）：

```
┌─────────────────────────────────────┐
│  通知额度池    [上课提醒 ▼]          │  ← 切换模板组 tab
├─────────────────────────────────────┤
│  日历视图：已囤日期显示 🔔（绿/响铃动画）│
│  8月27 28 29 ... 一直到「覆盖至」日期   │  ← remain 映射为「可覆盖天数」
├─────────────────────────────────────┤
│         [ 木鱼 / 大铃铛 ]            │  ← 主点击区
│         今日已囤 12 次               │
│         额度 +1 ↑ 飘字动画           │
├─────────────────────────────────────┤
│      [ + 屯 1 次 ]  大按钮           │  ← 与木鱼同逻辑
│  每日通知已开启    取消订阅            │
└─────────────────────────────────────┘
```

### 5.2 交互与微信技术

1. 用户**每次点击**木鱼或大 `+1` → 触发 `wx.requestSubscribeMessage({ tmplIds: [当前组 tmplId] })`。
2. 用户曾勾选「总是保持以上选择」→ **不弹窗**，静默 `accept`，后端 `remain + 1`（与 Readhub 一致）。
3. 首次或未勾选 → 正常弹窗；成功后播放**铃铛响铃 + 撒花**动画，日历上下一天亮起铃铛。
4. **映射规则**：`remain` 次 ≈ 日历上连续 N 个「可提醒日」标记（按该组最频场景：上课提醒=按天，待办=按次显示在列表旁数字即可，日历 primarily 给 `class_remind`）。

### 5.3 与木鱼结合

| 元素 | 作用 |
|------|------|
| 木鱼/铃铛 | 主点击区，解压 + 攒额度 |
| 「功德/额度 +1」飘字 | 即时反馈（图 2、3） |
| 今日敲击 N 次 | 游戏化计数（不设上限硬顶，但见防滥用） |
| 日历铃铛排期 | 可视化「我能安心用到哪天」 |

**调性**：教务场景用「小铃铛 / 松果」替代纯木鱼更贴品牌；木鱼可作为主题皮肤或「解压模式」开关。

### 5.4 防滥用与体验护栏

| 规则 | 说明 |
|------|------|
| 单次会话最多主动囤 **20 次** | 超出 Toast「今天先屯够啦，明天再来」 |
| 两次点击间隔 ≥ **800ms** | 防连点刷接口 |
| 微信返回 `20004` 主开关关闭 | 引导去微信设置，不无限弹 |
| 审计 | `auth-report` 记 `scene=quota_pool_tap` |

### 5.5 后端

- `remain` 纯次数；日历「覆盖至 YYYY-MM」= `f(remain, 组频率假设)` 前端展示用。
- 可选：`GET /subscribe-message/quotas` 增加 `displayCoveredUntil` 字段供日历渲染。

## 6. 额度流失 · 再激活（站内）

适用：教师不用薪资提醒、家长长期不打开等 → 额度过期消耗完，开关仍为开。

```
条件：notify-setting.enabled=true && remain=0 && 14天无该组 send 成功
  → 站内 Dialog / 消息中心：
     「还要继续收到【上课提醒】吗？」
     [继续提醒] → 跳囤额度页
     [关闭这类提醒] → PUT notify-settings 关闭
```

**频率**：同组 14 天最多 1 次；用户选关闭则永不再问。

## 7. 频率与「被迫点击」红线

| ✅ 合适 | ❌ 不合适 |
|--------|----------|
| 业务成功后的 **弹框** / **弹窗**（用户点按钮才调微信） | 每次 `onShow` 无 pending 也弹框 |
| 额度不足 **横幅** 24h 1 次 | 添加班级每个学员弹一次 |
| pending 队列合并同类事件 | 未点名必须先订阅才能点名 |
| 囤额度页用户主动点击 | 自动循环调 subscribe API |
| 协作新待办 **弹框** 只引导查看 | 冷启动直接微信订阅面板 |

**估算家长周频**（上课 3 次/周）：绑定囤 3 + 课后续 3 + 进小程序补 1 ≈ 7 次/周，可覆盖。

**估算教师周频**：点名 3×续杯 + 排课 1 + 囤额度页偶尔 5 ≈ 10 次/周。

## 8. 充值 / 线索 / 邀请（已定）

| 场景 | 策略 |
|------|------|
| 创建线索 | 成功后续 `todo_remind`；每次写跟进再续 |
| 添加学员 | 预囤 `package_alert` + `todo_remind` |
| 充值成功 | 顾问续杯 + **邀请家长**为独立按钮，老师点邀请时再走分享/家长侧订阅 |
| 点名授权 | **提交成功后** Sheet；创建班级 **保存时** 一次，非每学员 |
| 每按钮最大化 | 凡「保存/提交/发送」成功页，次要 CTA 统一为「为下次提醒屯 1 次」 |
