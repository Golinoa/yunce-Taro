## 四、页面路由守卫矩阵（运行前校验）

来源：`PAGE_ROLE_REQUIREMENTS`。未列出的已登录页默认开放；列出页必须命中角色，否则 Toast「无权限」并 `switchTab` 首页。

| 页面类别 | 允许角色 |
|---|---|
| 经营数据 Tab + `package-statistics/*` | admin, principal |
| 主题颜色、待办提醒设置页 | admin, principal |
| 角色权限、预警阈值 | **仅 admin** |
| 门店入驻 | admin, principal |
| 薪资管理首页/发放/模板等 | admin, principal |
| 薪资详情 | Staff（teacher 看本人） |
| 教师/员工列表与表单 | admin, principal |
| 考勤 | Staff |
| 学员相关 CRUD | Staff |
| 课程/科目/卡种/分类配置 | admin, principal |
| 卡会员列表 | Staff |

模块二次校验：`PAGE_MODULE_MAP` + `ROLE_PERMISSION_MAP` / 持久化 grants（授权 UI 未全落地时以后者为准）。

## 五、实现约定（改权限时遵守）

1. **Tab 级隐藏**：必须改 `custom-tab-bar` 的 `buildTabList`；禁止只靠 `setTabBarItem` 清空文案。  
2. **入口隐藏 ≠ 安全**：关键入口隐藏的同时，对应页面必须进 `PAGE_ROLE_REQUIREMENTS` 并 `withRouteGuard`。  
3. **系统设置项**：用 `adminOnly` / `managerOnly` / `hideForParent` 三层标记，避免「只藏家长、教师仍可见」。  
4. **我的页**：Manager 专属块用 `isManagerRole`；Staff 共用块用 `isStaffRole`；家长块用 `!isStaffRole`。  
5. **Mock 对照**：左上角 `MOCK` 胶囊按 `姓名(角色)` 切换账号，用于回归本矩阵。  
6. **后端**：本文件只覆盖前端体验与路由兜底；敏感写操作必须以服务端鉴权为准。
