# 会员待付款：倒计时关单与下单限制（设计约定）

> 状态：设计稿，未实现。交互稿见 [`membership-pay-pending.html`](./membership-pay-pending.html)；列表待付态已并入 [`membership-orders.html`](./membership-orders.html)。

## 导航栏（落地必遵）

- 实际实现使用**微信小程序原生导航栏**（`navigationStyle: default` + `navigationBarTitleText`），不要照搬 HTML 假顶栏做 custom。
- 「订单详情」入口：原生栏下方、**会员卡外**内容区右上角（胶囊区无法放自定义文案）。

## 目标

1. 用户关掉微信支付后，仍能感知「订单还在」，并用倒计时帮助决策、制造适度紧迫感。
2. 关单窗口从 30 分钟改为 **2 小时**，减少误关。
3. 限制短时间大量重复待付单（防刷库），真实用户以 **续付同一笔** 为主路径，不被硬挡。

## 关单与倒计时

| 项         | 约定                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| TTL        | 创建后 **2 小时** 未付 → `CLOSED`（`failReason: timeout`）                  |
| 前端倒计时 | 用服务端下发的 `expiresAt`（或等价字段），本地只做展示，不以本地时钟估过期  |
| 展示格式   | `HH:MM:SS`，到 0 后状态切「已关闭」，去掉继续支付                           |
| 出现位置   | ① 取消支付后底部 sheet ② 会员选购页待付条 ③ 订单列表置顶 ④ 待付详情大倒计时 |

## 防刷策略（对真实用户友好）

### 主策略：一人一笔待付

- 同一用户（建议按机构维度）已有未过期 `PAYING` 时，再次点「去支付」：
  - **不新建订单**
  - 返回已有单的支付参数 / 引导弹窗：「你有一笔待付款订单」→ **继续支付** / **查看订单**
- 换 SKU 也先处理待付单，避免一人堆积多笔待付。

### 兜底：软限流

- 正常「续付」不算新建，不计入限流。
- 建议：同一用户 **10 分钟内最多新建 3 笔**（极端连点、脚本）。
- 文案：`下单过于频繁，请稍后再试`（不暴露技术细节）。

### 主动关闭

- 待付详情可提供「关闭订单」（设计稿已画）。
- 关闭后释放待付槽位，可立即重新选购。
