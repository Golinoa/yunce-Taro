## 一、核心设计原则

### 1.1 第一性原理

> **人是核心实体，身份是人与机构的关系。**

一个自然人可以和多个机构产生多种关系：
- 张三管理机构A（校长）同时也在授课（教师）
- 李四在机构A授课（教师）同时孩子也在机构A上课（家长）
- 家长可能绑定不同校区的不同孩子

因此：**一个账号可以拥有多种身份**，身份是可叠加的关系层，不是互斥的账号类型。

### 1.2 设计哲学

| 原则 | 说明 |
|------|------|
| 先让人进来 | 降低注册门槛，可选信息一律支持"稍后补充" |
| 身份可叠加 | 注册时选一个主身份，后续可添加其他身份 |
| 上下文隔离 | 每次操作在某个身份上下文中进行，数据不串 |
| 预留扩展位 | 手机号登录、激活码、邀请码体系预留设计位 |

## 二、完整用户流程

### 2.1 认证流程总览

```
┌─────────────────────────────────────────────────────────────────┐
│                        打开小程序                                │
│                           │                                     │
│                    已登录？├── 否 ──→ 登录页                     │
│                           │              │                      │
│                           │         有账号？├── 是 ──→ 登录页   │
│                           │              │   (微信一键登录优先)  │
│                           │              │   (用户名/手机号备选) │
│                           │              └── 否 ──→ 注册流程     │
│                           │                      │              │
│                           │              Step1: 基础信息         │
│                           │              (用户名/密码)           │
│                           │                      │              │
│                           │              Step2: 选择身份         │
│                           │              (校长/教师/家长，必填)  │
│                           │                      │              │
│                           │              Step3: 角色信息         │
│                           │              (机构/校区码/孩子)      │
│                           │                      │              │
│                           │              注册成功 → 自动登录      │
│                           │                                     │
│                           └── 是 ──→ 单身份？├── 是 ──→ 直接进入 │
│                                          │                      │
│                                          └── 否 ──→ 选择身份    │
│                                                   → 进入对应首页│
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 登录流程

```
登录页
  ├── 顶部：品牌 Logo + 欢迎标题（淡淡蓝色背景）
  ├── 中部：装饰插画 / 留白
  ├── 底部操作区
  │   ├── 微信一键登录（主按钮，花瓣蓝渐变）
  │   ├── 手机号登录（次按钮，点击展开表单）
  │   ├── 用户名/密码登录（折叠，最弱入口）
  │   ├── 协议勾选
  │   └── 注册引导
  └── 登录成功后：
        ├── 单身份 → 直接进入对应首页
        └── 多身份 → 弹出身份选择 → 进入对应首页
                      （记住上次选择为默认）
```

### 2.3 注册流程（三步走）

```
Step 1: 创建账号（身份无关）
  ├── 用户名（必填）
  ├── 密码（必填）
  └── 邀请码（选填，拉新邀请码，通用，直接展示）

Step 2: 选择身份
  ├── 我是校长 → Step 3a
  ├── 我是教师 → Step 3b
  └── 我是家长 → Step 3c
  （不可跳过，不同身份对应不同首页和功能入口）

Step 3a: 校长信息
  ├── 机构名称（必填）
  ├── 机构地址（选填，稍后补充）
  ├── 负责人手机号（必填）
  └── 完成注册 → 直接进入校长首页

Step 3b: 教师信息
  ├── 校区码（选填，输入校区码绑定校区）
  └── 稍后绑定 → 完成注册 → 进入教师首页

Step 3c: 家长信息
  ├── 学生邀请码（选填，输入后绑定孩子）
  └── 稍后绑定 → 完成注册 → 进入家长首页
```

### 2.4 身份切换流程

```
App 内任意页面
  └── 点击身份指示器（顶部或"我的"页）
        └── 身份切换面板
              ├── 当前身份高亮
              ├── 其他已拥有身份列表
              ├── "添加新身份"入口
              └── 切换后：
                    ├── 首页内容切换
                    ├── TabBar 功能切换
                    └── 数据上下文切换
```

### 2.5 添加新身份流程

```
"我的"页面 → 身份管理 → 添加新身份
  ├── 选择要添加的身份
  ├── 补充该身份所需信息
  │   ├── 校长：机构信息（直接注册，无需激活码）
  │   ├── 教师：校区码
  │   └── 家长：学生邀请码
  └── 添加成功 → 可切换到新身份
```

## 三、码体系设计

### 3.1 码类型定义

| 码类型 | 用途 | 格式 | 何时输入 | 关联 |
|--------|------|------|---------|------|
| 拉新邀请码 | 老带新，双方奖励 | 6位字母数字 | 注册 Step1 选填 | 通用 |
| 校区码 | 教师绑定到某个校区 | 6位字母数字 | 注册 Step3b / App内 | 教师→校区 |
| 学生邀请码 | 家长绑定到某个孩子 | 8位字母数字 | 注册 Step3c / App内 | 家长→孩子 |

### 3.2 码的生成规则

- 校区码：由校长在校区设置中生成，一个校区一个码
- 学生邀请码：由教师在学员详情中生成，一个学员一个码，一次性使用
- 拉新邀请码：每个用户自动生成一个，固定不变

## 四、数据模型

### 4.1 核心实体关系

```
User (账号)
  ├── id
  ├── username
  ├── name
  ├── password_hash
  ├── phone (预留)
  ├── invite_code (拉新码)
  └── created_at

UserRole (身份关系，一个User可有多个)
  ├── id
  ├── user_id → User.id
  ├── role: 'principal' | 'teacher' | 'parent'
  ├── org_id → Organization.id
  ├── campus_id → Campus.id (教师/校长)
  ├── status: 'active' | 'pending'
  └── is_primary: boolean (是否为主身份)

Organization (机构)
  ├── id
  ├── name
  ├── address
  ├── owner_id → User.id (创建者)
  ├── owner_phone
  └── status: 'active'

Campus (校区)
  ├── id
  ├── org_id → Organization.id
  ├── name
  ├── campus_code (校区码)
  └── created_at

ParentChild (家长-孩子绑定)
  ├── id
  ├── parent_user_id → User.id
  ├── student_id → Student.id
  ├── invite_code (绑定用的邀请码)
  ├── status: 'active' | 'pending'
  └── bound_at
```

### 4.2 身份与权限矩阵

| 功能 | 校长 | 教师 | 家长 |
|------|------|------|------|
| 机构管理 | ✅ | — | — |
| 校区管理 | ✅ | — | — |
| 教师管理 | ✅ | — | — |
| 班级管理 | ✅ | ✅(本校区) | — |
| 课程管理 | ✅ | ✅(本校区) | — |
| 学员管理 | ✅ | ✅(本校区) | — |
| 课时消课 | ✅ | ✅ | — |
| 课时充值 | ✅ | ✅ | — |
| 查看孩子课时 | — | — | ✅ |
| 查看上课记录 | ✅ | ✅(本校区) | ✅(本孩子) |
| 统计分析 | ✅(全机构) | ✅(本校区) | — |
| 薪资管理 | ✅ | ✅(本人) | — |

## 五、页面与交互规范

### 5.1 登录页

| 元素 | 规范 |
|------|------|
| Logo | 居中，渐变圆形背景 |
| 品牌名 | "云策教务" + slogan |
| 顶部背景区 | 淡淡蓝色渐变 + 光斑，品牌 Logo + 欢迎标题 |
| 中部区域 | 装饰插画 / 留白，平衡视觉重心 |
| 微信一键登录 | 底部主按钮，花瓣蓝渐变，带微信图标 |
| 手机号登录 | 次按钮，Outline 样式，点击展开验证码表单 |
| 用户名/密码 | 折叠收起，最弱入口 |
| 协议 | 勾选框 + 用户协议/隐私政策链接 |
| 注册引导 | "还没有账号？立即注册" |

### 5.2 注册 Step1 - 基础信息

| 元素 | 规范 |
|------|------|
| 步骤指示器 | 1/3 圆点进度 |
| 标题 | "创建账号" |
| 用户名 | 必填，仅字母数字下划线 |
| 密码 | 必填，至少6位 |
| 邀请码 | 选填，直接展示 |
| 下一步按钮 | 花瓣蓝渐变 |

### 5.3 注册 Step2 - 选择身份

| 元素 | 规范 |
|------|------|
| 步骤指示器 | 2/3 圆点进度 |
| 标题 | "选择您的身份" |
| 校长卡片 | 琥珀橙色系，mdi-school 图标 |
| 教师卡片 | 花瓣蓝色系，mdi-teach 图标 |
| 家长卡片 | 花瓣紫色系，mdi-account-heart 图标 |
| 跳过选择 | 不提供，必须选择身份 |

### 5.4 注册 Step3 - 角色信息

**校长**：
| 字段 | 必填 | 说明 |
|------|------|------|
| 机构名称 | 是 | 创建新机构 |
| 机构地址 | 否 | 稍后补充 |
| 负责人手机号 | 是 | 机构联系方式 |

**教师**：
| 字段 | 必填 | 说明 |
|------|------|------|
| 校区码 | 否 | 输入后绑定校区，可稍后绑定 |

**家长**：
| 字段 | 必填 | 说明 |
|------|------|------|
| 学生邀请码 | 否 | 输入后绑定孩子，可稍后绑定 |
| 可绑定多个孩子 | — | 不同校区的孩子也可绑定 |

### 5.5 身份切换

| 元素 | 规范 |
|------|------|
| 入口 | "我的"页面顶部身份卡片 + 全局身份指示器 |
| 切换面板 | 底部弹窗，列出所有已拥有身份 |
| 当前身份 | 高亮 + 勾选标记 |
| 添加身份 | 面板底部"添加新身份"按钮 |
| 切换动画 | 面板关闭 → 页面内容渐变切换 |
