# 消课流程 — UI 设计审查报告

> 审查日期：2026-06-14
> 审查范围：原型文件 + 设计规范
> 问题统计：P0: 2 / P1: 2 / P2: 2

---

## 一、业务流程验证

### 核心流程
```
学员消课: 选学员 → 自动匹配课包 → 填课时/时间/内容 → 确认消课
班级消课: 选班级 → 勾选签到学员 → 填课时/时间/内容 → 确认消课
```

### P0 严重问题

#### P0-1: 消课未实际扣减课时数据
**问题**: `submitLesson` 只显示Toast提示，未实际扣减课包余额(`pkg.remaining`)和学员课时。这是消课的核心功能，当前仅是UI演示。

**影响范围**: 核心业务不可用
**建议**: 确认消课后需：1) 扣减课包 `remaining`；2) 记录消课日志（学员+课包+课时+时间+老师）；3) 更新班级已消课时；4) 更新学员剩余课时。

#### P0-2: 班级消课未逐学员扣减
**问题**: 班级消课模式下，每个学员可能匹配不同课包（科目不同/余额不同），但当前只显示每人扣同一课时数，未展示每位学员的实际课包匹配和扣减情况。

**影响范围**: 数据准确性
**建议**: 班级消课确认前，应展示每位签到学员的课包匹配结果和扣减预览，类似"张小明-钢琴课包-扣1课时(剩17) / 李思思-通用课包-扣1课时(剩9)"。

## 二、缺失项识别

### P1 重要问题

#### P1-1: 跨科目消课仅提示未走审批流程
**问题**: 单人消课时，如果班级科目与课包科目不匹配，只显示"已自动发起课包科目变更申请"，但无审批流程、无审批人、无状态跟踪。

**建议**: 明确跨科目消课的处理方式：1) 直接允许（灵活模式）；2) 需主管审批（严格模式）；3) 记录但不阻止（审计模式）。建议采用方案3，消课正常进行但标记为"跨科目"供后续审计。

#### P1-2: 缺少消课撤销功能
**问题**: 消课是敏感操作，一旦确认无法撤销。误操作（如选错学员、填错课时）无法补救。

**建议**: 增加"撤销最近一次消课"功能（限时24小时内），或在消课记录中增加"撤销"按钮（需二次确认+填写原因）。

## 三、设计一致性

### P2 一般问题

#### P2-1: 学员消课模式缺少班级关联
**问题**: 学员消课模式下，选择学员后未要求选择班级，无法将消课记录关联到具体班级。虽然设计中有"上课时间"字段，但缺少班级维度。

**建议**: 学员消课模式下增加"关联班级"选填项，便于后续按班级统计消课记录。

#### P2-2: 班级消课缺少教学内容和评分
**问题**: 班级消课模式下只有课时和时间的输入，缺少"教学内容"、"学生表现"和"课后作业"字段，与学员消课模式信息不对称。

**建议**: 班级消课模式也应支持教学内容和评分输入（统一填写，应用到所有签到学员）。

## 四、与其他模块的关联风险

| 关联模块 | 风险 |
|----------|------|
| 学员管理 | 消课扣减需同步更新学员剩余课时，欠课状态需实时更新 |
| 班级管理 | 班级消课需更新班级已消课时，签到记录需写入班级上课记录 |
| 教师管理 | 消课记录关联教师，需更新教师课时统计和薪资计算 |
| 课时充值 | 课包余额扣减需与充值模块数据一致，跨科目消课涉及课包科目变更 |
| 校区设置 | 科目列表应从校区设置动态获取，消课时科目匹配需与设置一致 |
