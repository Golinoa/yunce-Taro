# 添加学员 — UI 设计审查报告

> 审查日期：2026-06-14
> 审查范围：原型文件 + 迁移文档 + 项目问题记录
> 问题统计：P0: 1 / P1: 3 / P2: 2

---

## 一、业务流程验证

### 核心流程
```
填写基本信息(姓名/性别/电话) → 添加联系人(选填) → 选择新生/老生 → 填写课时信息(新生必填) → 收费信息(选填,含分期) → 保存学员
```

### P0 严重问题

#### P0-1: 保存学员未写入数据
**问题**: `saveForm` 仅做表单校验，通过后显示 `alert('表单校验通过！（演示效果，未真实提交）')`，未创建学员记录。

**影响范围**: 核心功能不可用
**建议**: 保存后需：1) 创建学员记录（姓名+性别+电话+联系人）；2) 如为新生，创建初始课包（课时+有效期）；3) 如有收费，创建收费流水；4) 跳转回学员列表页。

## 二、缺失项识别

### P1 重要问题

#### P1-1: 老生模式缺少课包选择
**问题**: 选择"老生"后，课时信息区域隐藏，但老生转来后需要关联到现有课包或创建新课包，当前设计未考虑此场景。

**建议**: 老生模式下应显示"关联课包"选项：1) 选择已有课包（从学员现有课包列表中选择）；2) 创建新课包（跳转课时充值页）；3) 暂不关联（仅建档，后续充值）。

#### P1-2: 联系人最多2人限制不合理
**问题**: 联系人最多只能添加2个（`contactCount >= 2` 即禁止添加），但实际业务中可能有3-4位家长/监护人需要绑定。

**建议**: 联系人上限改为5人，或至少3人。同时需与学员详情页的"家长"Tab数据联动。

#### P1-3: 缺少班级关联入口
**问题**: 添加学员时无法直接将学员加入班级，需先创建学员后再到班级详情页手动添加，操作路径长。

**建议**: 在课时信息区域下方增加"加入班级"选填项（从班级列表中选择），保存学员时自动加入对应班级。

## 三、设计一致性

### P2 一般问题

#### P2-1: 分期付款与课时充值模块重复
**问题**: 添加学员表单中包含完整的分期付款功能（期数选择+还款计划+金额校验），与课时充值模块的分期功能完全重复。

**建议**: 分期付款应抽取为独立的 `InstallmentPanel` 组件，添加学员和课时充值共用。当前项目已有该组件(`src/components/InstallmentPanel`)，迁移时直接复用。

#### P2-2: 新生课时与课包模板未关联
**问题**: 新生模式下直接输入课时数，未与校区设置的课包模板关联。应支持从课包模板快速选择。

**建议**: 新生课时区域增加"选择课包模板"快捷入口，选择后自动填充课时+有效期+价格。

## 四、与其他模块的关联风险

| 关联模块 | 风险 |
|----------|------|
| 学员管理 | 保存学员后需在学员列表中立即可见，数据需同步 |
| 班级管理 | 学员加入班级需在班级详情学生列表中同步显示 |
| 课时充值 | 新生初始课包创建需与课时充值模块数据模型一致 |
| 校区设置 | 课包模板应从校区设置获取，科目选择需与设置一致 |
