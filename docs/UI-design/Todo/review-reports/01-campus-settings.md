一、现有业务模块梳理
模块	页面/弹窗	核心功能

二、逻辑断层与冲突点（P0 严重）
1. 校区图标分配机制缺失
问题：添加校区表单中没有图标选择入口。当前分校区卡片硬编码了 🏢/✏️/🏫，但用户添加新校区时无法选择图标。

主校区 = 👑，分校区 = 🏢，合作机构 = ✏️ — 这是隐含规则，没有在UI中体现
用户提问"icon准备怎么分配"——说明这个逻辑不清晰
建议：图标应与校区类型自动绑定，不需要用户手动选。规则：

主校区 → 👑（自动，不可改）
自营分校区 → 🏢（自动）
合作机构 → ✏️（自动）
图标是类型标识，不是装饰，应从表单中移除选择，由类型自动决定
2. "切换校区"与"校区设置"的作用域混淆
问题：主页顶部的校区卡片切换了"当前查看的校区"，但下方的通知设置、发薪日、科目、节假日、课时单价——这些设置是全局的还是跟随当前校区的？

切换到保利校区后，科目列表变了吗？发薪日变了吗？
如果每个校区独立配置，那所有子页面标题应标注当前校区名
如果是全局配置，那切换校区只影响顶部卡片展示，容易误导用户
建议：明确业务规则——

全局配置（机构级）：发薪日、薪资模板、通知设置 → 切换校区不影响
校区级配置：科目、课时单价、节假日 → 切换校区后应显示对应校区数据
在校区级配置的子页面标题栏显示当前校区名，如"校区科目 · 保利校区"
3. "设为主校区"后数据联动缺失
问题：确认弹窗提示"原主校区将变为自营分校区"，但 doSetMain() 只弹了Toast，没有实际数据变更逻辑：

主页卡片信息没有更新
分校区管理页的卡片没有重新排列
校区选择器中的标签没有变更
CAMPUSES 数据没有更新
建议：doSetMain() 需要完整实现：

更新 CAMPUSES 数据中两条记录的 type
刷新主页卡片
刷新分校区管理页列表
刷新校区选择器
4. 删除校区无二次确认
问题：删除校区直接 showToast('已删除')，没有确认弹窗。删除校区是高风险操作，可能关联学生、教师、课时数据。

建议：增加删除确认弹窗，提示"删除后该校区下的X名学生、X名教师数据将如何处理"。

三、缺失的业务步骤与功能模块（P1 重要）
5. 添加校区表单字段不完整
缺失字段：

❌ 校区图标选择（或自动分配规则说明）
❌ 校区负责人/联系人（与联系电话不同）
❌ 校区营业状态（营业中/筹备中/已关闭）
❌ 校区面积/教室数量（影响排课）
❌ 校区经纬度（地图选点，用于学员端"附近校区"）
建议：至少补充"联系人"和"营业状态"，其余作为扩展字段。

6. 节假日缺少关键交互
缺失：

❌ 法定节假日不可编辑/删除的标识（当前看起来和自定义的一样可操作）
❌ 节假日的编辑/删除入口（自定义节假日应可编辑）
❌ 休息/上课的状态切换（调休日可能要上课）
❌ 重复规则设置（校庆日"每年9月1日"如何实现？当前是写死的）
❌ 节假日与校区的关联（不同校区寒暑假可能不同）
建议：

法定节假日加锁标识，不可编辑删除
自定义节假日加编辑/删除操作
增加"是否重复（每年）"开关
增加"调休上课"状态选项
7. 课时单价与科目的关联断裂
问题：科目页和课时单价页是两个独立页面，但业务上强关联：

课时单价页的科目列表与科目页不同步
删除科目后，对应的课时单价怎么办？
添加科目后，是否自动跳转设置单价？
建议：

课时单价页应直接从科目列表读取，而非硬编码
删除科目时检查是否有关联定价，有则提醒
添加科目后引导设置课时单价
8. 校区科目缺少校区维度
问题：科目列表是全局的，但不同校区开设的科目不同。保利校区可能没有钢琴教室，不应该显示钢琴科目。

建议：科目应支持按校区启用/停用，或在科目卡片上标注"已开通校区"。

建议：如果是即时保存模式，去掉全局保存按钮；如果是批量提交模式，需要在修改时标记脏数据。

问题：校区选择器中的列表是HTML硬编码的，与 CAMPUSES 数据和分校区管理页的数据完全独立。添加/删除校区后，选择器不会更新。
