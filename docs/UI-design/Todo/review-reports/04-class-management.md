# 班级管理 — UI 设计审查报告

> 审查日期：2026-06-14
> 审查范围：原型文件 + 设计规范 + 迁移方案
> 问题统计：P0: 2 / P1: 3 / P2: 3

---

## 一、业务流程验证

### 核心流程
```
班级列表 → 创建班级 → 班级详情 → 消课/编辑/结课
                ↓              ↓
           学员选择器      学生左滑→调班/移除
```

### P0 严重问题

#### P0-1: 消课未实际扣减课时
**问题**: `openLessonSheet` 打开消课弹窗后，点击"确认消课"只显示Toast"消课成功！"，未实际扣减学员课时和班级已消课时。`lessonStudentChecked` 收集了签到学员但未使用。

**影响范围**: 核心业务闭环断裂
**建议**: 确认消课后需：1) 扣减班级 `usedLessons`；2) 扣减每位签到学员的剩余课时；3) 记录消课日志（日期+课时+老师+签到学员）。

#### P0-2: 创建班级未写入数据
**问题**: `submitCreate` 只做表单校验和Toast提示，未将新班级数据写入 `classData`。创建后列表不会出现新班级。

**影响范围**: 核心功能不可用
**建议**: 创建后应将新班级push到classData，重新渲染列表。

## 二、缺失项识别

### P1 重要问题

#### P1-1: 调班弹窗无确认逻辑
**问题**: 调班弹窗(`transferSheet`)展示了班级列表，但点击班级后无确认操作，`closeTransferSheet` 只是关闭弹窗。调班是敏感操作，需二次确认。

**建议**: 点击目标班级后弹出确认："将「张小明」从「钢琴基础班」调至「舞蹈启蒙班」？"，确认后执行调班（从原班级移除+新班级添加）。

#### P1-2: 结课使用confirm()而非自定义弹窗
**问题**: `endClass` 使用浏览器原生 `confirm()`，与设计规范中的自定义弹窗风格不一致，且在移动端体验差。

**建议**: 改为自定义确认弹窗，与删除确认等保持一致。

#### P1-3: 移除学员无确认弹窗
**问题**: `removeStudentFromClass` 和 `removeStudentFromClassSp` 直接执行移除，无确认提示。移除学员可能导致课时数据丢失。

**建议**: 增加确认弹窗："确认将「张小明」从班级移除？该学员的课时记录将保留。"

## 三、设计一致性

### P2 一般问题

#### P2-1: 教师列表硬编码
**问题**: 创建/编辑班级弹窗中的教师选择(picker)是硬编码的4个教师名字，与教师管理模块数据不联动。

**建议**: 教师列表应从教师管理模块动态获取，仅显示在职(active)教师。

#### P2-2: 学员选择器按姓名匹配
**问题**: `togglePickerStudent` 使用姓名(name)作为唯一标识，同名学员会冲突。`pickerSelected` 是 `Set<string>`，无法区分同名学员。

**建议**: 使用学员ID作为唯一标识，而非姓名。

#### P2-3: syncCardDisplay匹配逻辑脆弱
**问题**: `saveEditClass` 中 `syncCardDisplay` 通过 `c.dataset.name===d.name` 匹配卡片，如果修改了班级名称则无法匹配到原卡片。

**建议**: 使用班级ID而非名称匹配，卡片data属性应存储classId。

## 四、与其他模块的关联风险

| 关联模块 | 风险 |
|----------|------|
| 教师管理 | 教师选择应从教师模块动态获取，教师离职后班级授课老师需处理 |
| 学员管理 | 学员课时扣减需与学员管理模块数据同步，调班需更新学员的班级归属 |
| 消课流程 | 消课是核心关联，课时扣减、签到记录、教师课时统计需保持一致 |
| 校区设置 | 班级应关联校区，当前设计未体现校区维度 |
| 课时充值 | 课时制班级的课时与充值模块关联，需确保扣减一致性 |
