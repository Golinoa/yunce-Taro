## 一、消课流程（已确认）

> 审查问题：P0: 2 / P1: 2 / P2: 2

### P0-1: 消课未实际扣减课包余额

**确认方案：FIFO 先进先出扣减**

```
扣减优先级：
1. 同科目课包 → 按到期日升序（最早到期先扣）
2. 课包内部 → 先扣"购买课时"，再扣"赠送课时"
3. 跨科目课包 → 首次需审批，通过后转为通用课包
```

**数据模型变更：**
- 课包需拆分为 `purchasedRemaining`（购买剩余）和 `bonusRemaining`（赠送剩余）
- 消课日志需记录：课包ID + 扣减来源(purchased/bonus) + 扣减数量

**确认消课后执行：**
1. 扣减课包余额（先购买后赠送）
2. 记录消课日志（学员+课包+课时+时间+老师）
3. 更新班级已消课时
4. 更新学员剩余课时

### 新增：结课处理机制

**三种场景：**

| 场景 | 处理 | 条件 |
|------|------|------|
| 误操作结课 | 同一班级恢复"进行中" | 结课7天内 |
| 正常结课+欠课 | 状态"已结课" + 课包冻结 + 支持补课 | — |
| 新一期开班 | 基于旧班新建（复制名称/科目/教师/校区，不复制学员和消课记录） | — |

**冻结课包的消课规则：**
```
自动匹配时：冻结课包 → 不参与匹配（排除）
手动选择时：冻结课包 → 可见+可选，但需额外确认

1. 正常消课 → 自动匹配活跃课包 → 冻结课包不出现在列表中
2. 学员无活跃课包 → 提示"该学员有1个冻结课包，是否使用？"
   → 点击"使用冻结课包" → 展示冻结课包详情 → 确认后扣减
3. 手动消课 → 课包选择器中冻结课包显示"🔒冻结"标签
   → 选中时弹确认："该课包已冻结（原班级已结课），确认使用？"
   → 确认后正常扣减

原则：冻结 ≠ 不可用，冻结 = 不自动扣，需主动确认
```

### P1-1: 老生模式缺课包关联

**确认方案：老生录入"存量课包"**

老生 = 系统上线前已在上课的学员，需录入历史剩余数据。

```
老生录入流程：
选择"老生"模式 → 填写基本信息 → 填写存量课时信息 → 保存 → 引导分班

存量课包表单：
  科目：[钢琴 ▼]
  剩余课时：[20]
  课时构成：
    ○ 全部为购买课时
    ○ 全部为赠送课时
    ● 不确定（按混合处理，FIFO统一扣减）
  有效期：[2026-12-31] / [永久]
  备注：[系统上线前存量]
  [+ 添加更多课包]  ← 支持多科目存量课包
```

关键设计点：
- 课时构成提供"购买/赠送/不确定"三选一，"不确定"按混合处理
- 历史消耗不录入明细，课包备注标注"系统上线前存量"
- 有效期手动填写（老生课包可能已过原定有效期但机构口头承诺继续有效）
- 老生录入不涉及收费，跳过收费步骤
- 支持添加多个存量课包（钢琴剩20节+书法剩10节）
