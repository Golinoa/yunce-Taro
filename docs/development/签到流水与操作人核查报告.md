# 签到流水与操作人 核查报告（2026-09-30）

## 一、大白话结论（先说结果）

- **补签到记录操作老师吗？** ❌ 不记录。小程序提交时确实带了一个"操作老师"字段，但**后端的入参校验不认这个字段，直接把它丢掉了**，所以库里没有。
- **正常签到记录操作老师吗？** ❌ 不记录。记录上只有一列"授课老师"。**更糟的是：校长/管理员操作时，这一列会被替换成"这个学员的归属老师"**——也就是说校长点了名，流水上写的是那位老师，**查不出是校长操作的**。
- **试听记录、上课记录能正确显示流水日志吗？** ❌ 不能。系统的"操作日志"表是现成的、查询页面也是现成的、前端连"点名签到/单人消课"的日志文案都写好了——**但没有任何一处把签到流水真正写进去**：
  - 后端：全仓**零处**写操作日志（只有"查"，没有"写"）；
  - 前端：唯一打算写日志的函数是个**空壳（调用即报错，被 try/catch 吞掉）**，注释写着"由后端业务写接口记录"，而后端从未实现。
- 结论：**"签到流水可追溯到操作人"当前不成立**。这是一条"两端都在、中间断掉"的链路，不是小 bug，需要补写入。

## 三、链路断点示意

```
[小程序] 点名/补签/试听签到
   │  携带 operator_teacher_id（班级/补录链路）
   ├─► 后端入参校验：不认该字段 → 丢弃        ← 断点 1
   │
   ├─► 消课记录表：只有 teacherId（授课老师）  ← 断点 2（无操作人列；
   │      且校长操作时被替换成"学员归属老师"）      校长操作无法追溯）
   │
   └─► 操作日志表 AuditLog：无任何写入        ← 断点 3（前端空壳 + 后端未实现）
            ↑
      查询接口/前端页面/中文标签 全部就绪（只差写入）
```

## 四、修复方案（分两档，请选一档实施）

### 方案 A（推荐，最小闭环，**不需要数据库迁移**）
1. **后端**：在消课记录"创建/修改/删除"与试听"签到/取消/恢复"的业务写接口里补写 `AuditLog`：
   - action：班级点名为 `lesson.checkin`（汇总一条）、单人消课/补录为 `lesson.record`、试听签为 `lesson.trial_checkin`（或在既有 action 内复用）；
   - userId/userRole = **真实操作者**（后端从 JWT 身份取，不信任前端传值）；detail 含学员、班级、日期、课时；targetId=记录 id。
   - 覆盖面：班级点名、补录签到、单人消课、**校长/管理员**（这条同时修掉"校长操作无法追溯"）。
2. **前端**：把 `auditLogService.record` 的空壳改为**不再抛错**（写日志已下沉后端，前端调用点直接删掉/空实现），避免无意义报错日志。
3. 效果：操作日志页可查到每条签到流水与操作人；消课记录详情页的「操作老师」如要显示真实操作人，需方案 B。

### 方案 B（完整，含**数据库迁移**）
在方案 A 基础上，给 `LessonRecord` 增加 `operatorTeacherId`（可空）列：
- 写入：创建/修改时记录真实操作者（校长操作也如实记录）；
- 展示：消课记录列表/详情的「操作老师」改为读该列（不再是授课老师冒充）；授课老师仍单独展示。
- 需要一次 Prisma 迁移 + 后端重新部署；历史数据该列为空，展示回落为"未记录"。

### 无论哪档都需要的部署动作
- 后端改动 → 重新部署 dev 后端（当前前端连 dev.chancore.cn）；本机 WSL 后端同步重启。

## 五、备注

- 试听记录页（`package-lead/pages/trial-records`）本身是"试听台账"，未展示操作人/流水入口；若要在该页直接看签到流水，可在方案 A 完成后加一个"查看操作日志"入口（小改动）。
