# 补课/试听作用域 与 节假日停课态 修复报告（2026-09-30）

## 一、大白话说明（先看这个）

**缺陷 A：在一节课上加了补课/试听，结果整条排课规则都出现了**

打个比方：你请一位客人来"9 月 30 日这场"课旁听，结果发现他出现在这家班"每一场"的座位表上。
我们查了所有能加人的门口（课表卡片约试听/补课、点名页添加学员、补录页、家长调课）和所有看名单的窗口（课表、点名页、缓存），
发现**每一扇门都只放行"指定那一天"**——代码里没有找到会"放全体"的漏洞。
唯一可能出事的地方：小程序完全信任服务器"只会返回当天名单"。如果服务器上跑的是旧版本（忘了按日期筛选），
就会把别的日子约的人也送过来——症状和你看到的完全一致。所以这次在小程序里加了一道**自己的安检**：
不管服务器返回什么，只留下"这一天"的名单。这样即使服务器是旧版，也不会再串。

**缺陷 B：节假日课程，卡片上有"放假停课"角标，点进详情页却看不到停课状态**

打个比方：学校门口挂了"今天放假"的牌子（卡片角标），但走进教室（详情页）发现黑板上一片空白，
讲台上还摆着一个"申请停课"的按钮——明明已经停了，按钮却还问你要不要停。
修复后：详情页顶部会挂上和卡片同款的橙色"放假停课"标；原来的"停课"按钮换成"恢复"。
点"恢复"会引导你把这一节课调到其他正常日期——**调过去的那一刻停课就自动解除了**（因为停不停课只看日期）。

## 三、缺陷 B：根因与修复

**根因**：节假日停课是**纯日期推导**，不落库——
`schedule-card-build.ts:181`：`holidaySuspended = 该日是机构放假日 && 排课规则 skip_holiday !== false`。
只有课表卡片消费了这个值；详情页（点名页 `lesson-form`）完全不知道，所以：头部无停课态、按钮还显示"停课"。

**修复（4 处 + 1 测试）**：

| 文件 | 改动 |
|---|---|
| `utils/schedule-lesson-nav.ts` | `LessonFormNavFields/NavParams` 增加 `holidaySuspended`，点名/补录/仅查看三条路都透传 `holidaySuspended=1` |
| `package-course/pages/lesson-form/index.tsx` | 读路由参数 `holidaySuspendedParam`；新增 `handleRestoreHolidayLesson`（弹窗确认 → 走单次调课） |
| `package-course/pages/lesson-form/ClassLessonPanel.tsx` | 头部日期旁挂橙色「放假停课」标；按钮区：有停课记录→「恢复本节课」（原逻辑优先）；纯节假日停课→「恢复」；都没有→「停课」 |
| `utils/schedule-lesson-nav.test.ts` | 新增用例：三条入口都带参数、未停课不带 |

**「调课到正常日期自动恢复」**：无需新代码。停课态按日期推导，调课目标日不是放假日，角标与详情页停课态自动消失；
源日期（放假日）的卡片因已被调走也不再展示。

**恢复按钮语义说明**：节假日停课没有落库的 cancelled 记录可删，所以不能走"恢复本节课"（那是删记录）。
它的"恢复" = 把这节课调到其他日期（单次调课只影响这一天，长期规则不动），这是当前数据模型下唯一真实可行的恢复方式。
